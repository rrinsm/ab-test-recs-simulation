# A/B-тест рекомендаций: симуляция и разбор

Это мой учебный проект по A/B-тестированию. Я хотела пройти весь путь анализа эксперимента сама, от разбиения пользователей до выводов, и проверить, что методы работают так, как о них пишут в учебниках.

Чтобы это проверить, я использую искусственные данные. Эффект в них я задаю заранее, поэтому знаю правильный ответ и вижу, находит ли его тест. Если эффекта нет, тест тоже не должен его придумывать.

## Сценарий
В мобильном приложении оператора появился новый блок рекомендаций. Пользователей (200 000 человек) случайно делят на две группы: контрольную и тестовую. Сравниваю три вещи:
- долю людей, которые кликнули по рекомендациям (CTR);
- число сессий на пользователя;
- долю обращений в поддержку (она нужна как защитная метрика, ее не должно испортить).

## Что делает скрипт
Весь код лежит в `ab_recs_experiment.py`. По порядку он делает следующее:
1. Создает пользователей и делит их на две группы случайно.
2. Загружает данные в SQLite и считает метрики по группам обычным SQL-запросом.
3. Проверяет, что группы получились примерно равными (SRM, критерий хи-квадрат).
4. Считает, сколько пользователей нужно, чтобы заметить эффект в 3% и в 5%.
5. Сравнивает CTR z-тестом для долей и строит доверительный интервал.
6. Сравнивает сессии t-тестом Уэлча, а потом с CUPED: в качестве ковариаты беру число сессий до теста.
7. Строит bootstrap-интервал и проверяет метрику поддержки.
8. Применяет поправку Холма, потому что метрик несколько.
9. 500 раз запускает A/A-тест, то есть делит пользователей случайно и сравнивает две одинаковые группы, чтобы убедиться, что ложных срабатываний около 5%.

## Что получилось
| Проверка | Результат |
|---|---|
| Размеры групп | 100 263 и 99 737, перекоса нет (p = 0.24) |
| CTR | 25.7% в контроле, прирост 3.15 п.п. (12.2% отн.), p < 0.001 |
| Сессии, обычный t-тест | прирост 1.2%, p = 0.0004 |
| Сессии, CUPED | дисперсия меньше на 74%, p около 1e-12 |
| Обращения в поддержку | без изменений (p = 0.42) |
| A/A-тест, 500 запусков | 5.6% ложных срабатываний при уровне 5% |

Самое заметное: сессии до теста и во время теста сильно связаны (корреляция 0.86), поэтому CUPED резко уменьшает разброс метрики. Тот же эффект можно заметить на меньшей выборке.

## Как запустить
```
pip install -r requirements.txt
python ab_recs_experiment.py
```
Результаты сохранятся в файл `results.json`.

## Ограничения
Данные искусственные, поэтому проект показывает, как я работаю с методами, и ничего не говорит о реальном продукте. В настоящем эксперименте добавились бы вопросы, которых здесь нет: сезонность, эффект новизны, пересечение с другими тестами.
